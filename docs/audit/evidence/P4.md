## 2. Definisi resmi field

- `vark` (per mahasiswa): kategori asal nilai yang relevan. Dengan filter kategori:
  kategori itu bila mahasiswa punya nilai tersimpan, selain itu `null`. Tanpa
  filter: kategori asal nilai feedback terbaru (`updated_at`), selain itu `null`.
  `null` = belum memberi feedback, bukan 0%.
- `originCategories`: semua kategori asal yang punya nilai tersimpan pada topik.
- `respondentCount`: jumlah mahasiswa pada cakupan filter yang punya nilai non-null.
- `mean`: rerata aritmetika nilai non-null pada cakupan filter (`null` bila tidak ada).
- `notRespondedCount`: **field kompatibilitas**; definisi lama dipertahankan
  (populasi enrollment ACTIVE pada cakupan filter dikurangi responden).
- `kinesthetic.assessedCount` / `meanScore`: seluruh nilai final tersimpan pada
  studi kasus topik, termasuk mahasiswa dengan enrollment LEFT / logout / VARK
  berubah; tidak memakai sesi atau enrollment.
- `kinesthetic.notSubmittedCount`: **field kompatibilitas**; definisi lama
  dipertahankan (mahasiswa dengan sesi Kinesthetic aktif yang belum mengirim).
  Bukan status individu FR-048.

## 3. Risiko kompatibilitas (perlu dicatat saat integrasi)

1. `StudentFeedback.vark` bisa `null`; mapping Android wajib nullable (sudah).
2. `students` kini selalu berisi seluruh populasi kelas (bukan hanya baris dengan
   feedback); klien lama yang menghitung rerata sendiri harus melewati `null`.
3. `notRespondedCount` didefinisikan ulang dari populasi enrollment aktif
   (bukan dari sesi VARK), sehingga angkanya bisa berbeda dari implementasi lama
   walau tetap field yang sama.
4. `notSubmittedCount` sengaja mempertahankan definisi lama (sesi aktif) agar
   kompatibel; angka ini tidak boleh dipakai sebagai status individu FR-048.
5. `definitions` adalah field tambahan; klien lama mengabaikannya.
6. Filter `studentId` untuk mahasiswa di luar kelas tetap `404 STUDENT_NOT_FOUND`;
   dosen di luar penugasan `403 CLASS_FORBIDDEN`; Admin `403 FORBIDDEN`.

## A1. Temuan dan konfirmasi source

menunjukkan populasi lama berbeda: mahasiswa enrollment ACTIVE di kelas yang
(a) memiliki nilai feedback pada topik untuk filter, ATAU (b) memiliki sesi
aktif terakhir dengan VARK Visual/Audio/Read-Write yang cocok filter; sesi
Kinesthetic tidak masuk populasi. `notRespondedCount` lama =
`populasi - respondentCount`.

## B6. Risiko / catatan

1. **String orphan:** `p4_analytics_not_responded_count` dan
   `p4_analytics_kinesthetic_compat_count` kini tak direferensikan UI (sengaja
   tidak dihapus agar perubahan minimal dan string tetap tersedia bila
   kebijakan berubah). Tidak berdampak runtime; dapat dibersihkan terpisah.
2. **Field API tetap dikirim backend** (`notRespondedCount`,
   `kinesthetic.notSubmittedCount`) dan tetap dipetakan ke domain/DTO; klien
   lain masih dapat memakainya. UI dosen tidak lagi menampilkannya.
3. **Status per mahasiswa "Belum merespons" tetap tampil** (diizinkan; konsep
   0% vs null) dan berasal dari `students[].vark == null`/`feedback == null`,
   bukan dari `notRespondedCount`. Dosen dapat melihat siapa yang belum
   merespons tanpa angka total kompatibilitas.
4. **Bukti layar memakai repository fake**, bukan backend. Bila diperlukan
   bukti E2E, jalankan Postgres + backend uji, login dosen, buka Analytics, dan
   ambil UIAutomator dump; status saat ini jujur **NOT RUN** untuk bagian itu.
5. Screenshot disimpan di `/tmp` (host) dan external files dir aplikasi di
   emulator; `connectedDebugAndroidTest` menghapus app sehingga file
   perangkat hilang bila app di-uninstall lagi.
6. Tidak ada perubahan Gradle cache/settings, tidak `clean`, tidak Gradle
   paralel; seluruh build memakai lock serial lintas agen.

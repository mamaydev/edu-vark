## Ruang lingkup

Paket 3 menutup gap FR-001, FR-034, FR-036 (lihat `docs/audit/SRS-CODEBASE-GAP-ANALYSIS.md` §4/§5, DEC-006/C1-01):

1. Login semua role memakai identitas numerik: NIM/NIDN akademik 10–11 digit, Admin persis `^014014[0-9]{5}$`. Username legacy `admin` ditolak (401).
2. Alokasi ID Admin otomatis `014014` + 5 digit (00001–99999), unik global lintas role, lewati kandidat terpakai, aman konkurensi, gap diperbolehkan.
3. Migrasi `002` mem-backfill seluruh Admin lama ke pola baru secara deterministik tanpa mengubah UUID/relasi/histori/password; preflight read-only melaporkan tabrakan & kapasitas tanpa data pribadi.
4. PATCH Admin: perubahan role + identitas dalam SATU transaksi; akademik→ADMIN memakai ID otomatis; ADMIN→akademik wajib NIM/NIDN valid & unik; gagal → rollback total; sesi lama dicabut; proteksi ubah-diri & Admin aktif terakhir dipertahankan.
5. Android: field login berlabel NIM/NIDN, hanya digit ASCII, berhenti menerima setelah 11 digit (ketik & tempel), tombol submit aktif hanya pada 10–11 digit; pembuatan akun Admin tanpa input ID (catatan ID otomatis); ubah role seperti aturan backend; pesan error server ditampilkan.

## Endpoint yang diverifikasi

- `POST /api/v1/auth/login` — format identitas per role (10/11 digit diterima; 9/12/huruf/`admin` ditolak 401).
- `POST /api/v1/admin/users` — create akademik (validasi & unik) dan create ADMIN (ID otomatis, input diabaikan, alokasi konkuren, ekshausti).
- `PATCH /api/v1/admin/users/:id` — role + identitas satu transaksi, rollback total saat target invalid/duplikat, pencabutan sesi.
- `GET /api/v1/admin/users`, `GET /api/v1/admin/users/:id`, reset password, deactivate, enrollment — regresi tetap hijau (suite admin).

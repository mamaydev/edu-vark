## 1. Ringkasan

Celah C1-02 ditutup: API berhenti menerbitkan URL bertanda tangan (signed URL) untuk
materi. Semua pembacaan isi materi FILE memakai **satu alamat tetap** yang selalu
mengotorisasi ulang setiap permintaan, dan materi LINK dibuka lewat endpoint
`link-target` yang memeriksa izin terkini. URL lama yang sudah telanjur terbit tetap
dilayani oleh reader legacy sampai kedaluwarsa alami (jendela transisi).

Kontrak baru:

| Endpoint | Peran | Fungsi |
| --- | --- | --- |
| `GET /api/v1/materials/:id/content` | STUDENT, LECTURER | Mengirim byte berkas privat dari storage setelah otorisasi penuh per permintaan. Mendukung `Range`/`If-Range`; setiap respons `Cache-Control: no-store`, `Vary: Authorization`. |
| `GET /api/v1/materials/:id/link-target` | STUDENT, LECTURER | Mengembalikan `{ data: { url } }` tujuan tautan eksternal HANYA setelah izin terkini diperiksa; menolak non-HTTPS. |

API tidak pernah lagi mengembalikan `signedUrl`/`expiresAt` terisi. Pada response materi
`FILE`: `signedUrl = null`, `expiresAt = null`, `contentUrl = /api/v1/materials/:id/content`.
Pada response materi `LINK`: `linkTargetUrl = /api/v1/materials/:id/link-target` dan `url`
lama tetap dipertahankan untuk kompatibilitas.

### Matriks otorisasi (diverifikasi lewat tes)

Setiap request (termasuk setiap request `Range`) melewati urutan:
`authenticate` (sesi aktif/tidak revoked/tidak expired, akun ACTIVE) →
`requireRole('STUDENT','LECTURER')` → `requirePasswordChanged` → otorisasi materi.

| Kondisi | Hasil |
| --- | --- |
| Sesi logout/revoked/expired, akun nonaktif | 401 (`SESSION_*`) |
| `mustChangePassword = true` | 403 `PASSWORD_CHANGE_REQUIRED` |
| Role ADMIN | 403 `FORBIDDEN` |
| Mahasiswa tanpa VARK | 428 `VARK_REQUIRED` |
| VARK materi ≠ VARK sesi | 403 `MATERIAL_VARK_FORBIDDEN` |
| Mahasiswa tidak terdaftar / enrollment bukan ACTIVE | 403 `NOT_ENROLLED` |
| Tidak ada baris materi / materi soft-deleted / topik soft-deleted | 404 `MATERIAL_NOT_FOUND` |
| Topik belum PUBLISHED atau kelas nonaktif (mahasiswa) | 404 `MATERIAL_NOT_FOUND` |
| Kelas nonaktif atau dosen bukan pengampu (dosen) | 404 `MATERIAL_NOT_FOUND` |
| ID bukan UUID / objek storage hilang | 404 `MATERIAL_NOT_FOUND` |
| `Range` malformed/multi-range/di luar batas | 416 `RANGE_NOT_SATISFIABLE` + `Content-Range: bytes */size` |
| `If-Range` tidak cocok | Range diabaikan, 200 penuh |

Dosen pengampu boleh membaca topik DRAFT (pratinjau) dan tidak terkena aturan VARK.

## 6. C1-02 — bukti kedaluwarsa lokal dan jendela transisi

- Berkas tes menyetel `R2_SIGNED_URL_TTL_SECONDS=1` **sebelum** `createApp()`.
- Tes membuat URL bertanda tangan lewat fungsi legacy `getSignedObjectUrl` (mensimulasikan
  tautan yang terlanjur terbit sebelum perubahan), lalu:
  - request pertama → **200**, byte identik, `Cache-Control: no-store`;
  - tunggu 2,2 detik (melebihi TTL 1 detik) → request kedua → **403 `SIGNED_URL_EXPIRED`**.
- Respons API materi setelah perubahan tidak memuat `signedUrl`/`signature=` (diassert
  dengan serialisasi JSON) dan `signedUrl` bernilai `null`.

**Jendela transisi** = waktu penerbitan terakhir URL lama + TTL maksimum yang berlaku.
Dengan implementasi saat ini `TTL = R2_SIGNED_URL_TTL_SECONDS` (default 300 detik).
Nilai TTL pada lingkungan produksi (R2) **NEEDS VERIFICATION** — harus dicek dari
konfigurasi env deployment; jendela transisi tidak boleh diumumkan sebelum nilai itu
dipastikan. Setelah jendela berakhir, reader legacy `material-files.routes.ts` dapat
dihapus pada paket lanjutan.

## 7. Risiko & hal yang belum terverifikasi

1. **Nilai TTL produksi NEEDS VERIFICATION** (`R2_SIGNED_URL_TTL_SECONDS`, default 300).
   Menentukan panjang jendela transisi C1-02.
2. **Klien Android lama** yang membuka `signedUrl` untuk materi FILE akan kehilangan
   akses setelah jendela transisi; klien baru pakai `contentUrl`. Perlu catatan rilis.
3. **R2 path belum diuji end-to-end** karena `backend/.env` tidak memiliki kredensial R2;
   tes memakai storage lokal privat. Kode `getObjectInfo`/`getObjectBody` memakai AWS SDK
   dan typecheck, tetapi integrasi R2 nyata NEEDS VERIFICATION.
4. **Range pada objek R2** diuji lewat storage lokal (stream + ETag sha256). Perilaku
   ETag/Last-Modified R2 perlu diverifikasi saat kredensial tersedia.
5. Uji beban/streaming berkas besar belum dilakukan.
6. Suite unit Android bersama masih 95/96 karena bug tes paginasi Paket 5; bukan

### 9.5.1 Eksekusi end-to-end lintas versi (Lead, 24 Nov 2026)

APK lama dibangun ulang dari `b7b6cd6`, backend baru dijalankan dari `dist/`
(DB `eduvark_restore_test`), backend lama dijalankan dari worktree `b7b6cd6`
(DB `eduvark_oldcompat`, hanya migrasi `001`), keduanya diakses emulator
`Pixel_10_Pro_XL` (API 37) lewat `adb reverse` dan base URL debug
`http://127.0.0.1:<port>/api/v1/`. Artefak payload/jawaban ada di
`docs/audit/evidence/compat-e2e/`.

**Android lama + backend baru (actual APK, controlled failures terkonfirmasi):**

- FILE: daftar materi memuat baris "Materi PDF Restore" tetapi payload berisi
  `signedUrl: null` dan `url: null`; mengetuk materi tidak membuka aktivitas apa pun
  (fokus tetap `MainActivity`) dan tidak ada isi yang bocor. Ini regresi yang memang
  diharapkan dari penghentian penerbitan signed URL.
- Analytics tanpa feedback: payload backend berisi `students[].vark = null`, sedangkan
  DTO lama mendeklarasikan `vark: String` (non-null). Layar menampilkan
  "Tidak dapat dimuat / Terjadi kesalahan. Coba lagi." — controlled failure yang
  memaksa pembaruan aplikasi sebelum backend baru dipakai.
- Login Admin: `loginId: "admin"` ditolak backend baru (401 `INVALID_CREDENTIALS`);
  ID Admin baru `01401400001` berhasil (200) tetapi tidak dapat diketik di klien lama.
  Klien lama harus dihentikan pada cutover.

**Android baru + backend lama (actual APK, controlled failures terkonfirmasi):**

- FILE: materi tampil dari daftar lama; mengetuknya memanggil
  `GET /api/v1/materials/:id/content` yang tidak ada di backend lama (404
  `ROUTE_NOT_FOUND`). Aplikasi menampilkan "Materi tidak dapat dibuka / Materi ini
  tidak tersedia lagi atau Anda tidak memiliki izin untuk membukanya."
- Analytics: halaman dapat dimuat (empty state "Belum ada data untuk ditampilkan"),
  karena field baru absen dan `vark` lama non-null; ini pasangan baca yang tidak
  berbahaya tetapi **bukan pasangan rilis** karena materi dan Admin tidak kompatibel.
- Login Admin: `01401400001` ditolak backend lama (401), sedangkan `admin` ditolak
  validasi klien baru ("Hanya angka 0–9, maksimal 11 digit.").

**Android lama + backend lama:** baseline pra-cutover; tidak dieksekusi ulang pada
remediasi ini (kontrak signed URL lama sudah menjadi perilaku rilis sebelumnya).

**Android baru + backend baru:** pasangan rilis; dibuktikan suite backend final
213/213, Android unit final 130/130, instrumentasi final 14/14 (termasuk tes Analytics
C1-05), dan smoke restore pada bagian ini. Hasil kompatibilitas nyata terbaru ada di
`docs/audit/evidence/ROLLOUT-RUNBOOK.md`.

Catatan status bukti:

- Seluruh baris matriks kini memiliki bukti eksekusi nyata kecuali
  Android lama + backend lama (baseline; **NOT RUN** pada remediasi ini, bukan
  pasangan rilis).
- Analytics klien baru tetap memakai `vark` nullable dan `originCategories` default;
  data lama yang tidak memiliki field tersebut dimuat tanpa crash.
- Login Admin lintas versi tidak dapat "diizinkan" untuk kedua arah: klien lama hanya
  mengenal `admin`, backend baru hanya mengenal ID numerik; cutover harus serentak
  atau didahului jendela transisi yang disetujui Owner.

**Rencana cutover/rollback (butuh persetujuan Owner):**

1. Rilis backend baru lebih dulu; umumkan bahwa `signedUrl` berhenti diterbitkan.
2. Paksa pembaruan klien minimal sebelum jendela transisi berakhir
   (`signedUrl` terakhir terbit + `R2_SIGNED_URL_TTL_SECONDS`; nilai produksi
   **NEEDS VERIFICATION**).

4. Rollback: bila perlu kembali ke backend lama, klien baru tidak bisa membuka FILE
   lewat `/content` (404) — rollback hanya aman bila disertai rollback klien lama
   atau patch backend yang menambahkan `contentUrl`; jangan campur klien baru dengan
   backend lama.
5. Matriks ini dan keputusan akhir cutover **BUTUH PERSETUJUAN OWNER**.
